「なに食べたい？」の機能ごとに、**何ができて、どんなルールで動くか**をまとめたもの。今リリースしている機能だけを書く（作業中の機能は、リリースしてから足す）。

- 画面のつながりは [DESIGN.md](DESIGN.md)、データの形は [DATABASE.md](DATABASE.md)
- 「なぜそうしたか」は [HANDOFF.md](../HANDOFF.md) を参照し、ここには二重に書かない

**機能を変えたら、ここも一緒に直す。**

## すべての機能に共通するルール

| ルール | 内容 | 場所 |
|---|---|---|
| ログインが必要 | ログイン以外の画面は、ログインしていないと開けない（F-01） | `components/common/RequireAuth.tsx` |
| データは夫婦で共通 | レシピ・リクエスト・買い物リスト・メモ・作ったご飯は、2人とも同じものを見て、同じように書き換えられる。例外はシークレットモードの設定（人ごと） | RLS（[DATABASE.md](DATABASE.md)） |
| 相手の変更の反映 | 自動では届かない（リアルタイムの同期はしていない）。アプリに戻ったとき（画面が前に出たとき）に読み直す。読んでから30秒以内は読み直さない | `utils/queryClient.ts` |
| 読み込みに失敗したとき | 「読み込めませんでした」と「もう一度読み込む」ボタンを出す | `components/common/LoadError.tsx` |
| 保存に失敗したとき | 画面の上にトースト（赤）で知らせる。文言はエラーの種類で決める（下の表）。入力した内容は消さない | `utils/dbError.ts` |
| 保存できたとき | 必要なところだけトースト（黒）で知らせる（例：「レシピを追加しました」） | `contexts/ToastProvider.tsx` |
| 二重に押せない | 保存中はボタンを押せなくする | 各画面 |
| すぐに反応する操作 | お気に入りの ★、買い物リストのチェック、シークレットモードの切り替えは、押した瞬間に表示を変える。保存に失敗したら元に戻す（楽観的更新） | `hooks/` |

### 保存に失敗したときの文言

| 原因 | 文言 |
|---|---|
| 電波がない・サーバーに届かない | 通信できませんでした。電波のよいところでもう一度お試しください |
| 同じものがすでにある（一意制約） | すでに入っています |
| 入力が決まりに合わない（check 制約） | 入力内容を確認してください |
| ほかのデータから使われている（外部キー） | ほかのデータから使われているため、変更できません |
| 権限がない | 権限がありません。ログインし直してください |
| 対象が見つからない（DB 関数のエラー） | 見つかりませんでした。ほかの人が先に変更したかもしれません |
| ログインの期限切れ | ログインの期限が切れました。ログインし直してください |
| それ以外 | うまくいきませんでした。時間をおいてもう一度お試しください |

## F-01 ログイン・ログアウト

**目的**：夫婦2人だけが使えるようにする。

**画面**：ログイン（`/login`）、設定のログアウト

**入力**

| 項目 | 必須 | 決まり |
|---|---|---|
| メールアドレス | ✓ | 前後の空白は取り除く |
| パスワード | ✓ | |

**処理・ルール**
- ログインしたら、ログイン前に開こうとしていた画面へ移る（なければレシピ一覧）
- すでにログインしているときにログイン画面を開くと、そのまま移る
- **新規登録はできない**。アカウントは管理者が Supabase のダッシュボードで作る。パスワードを変える機能もない
- ログインは、ログアウトするまで続く（毎回入力しなくてよい）。スマホをなくしたときは、ダッシュボードでパスワードを変えるとログインが切れる
- iPhone のパスワードの自動入力が使える
- ログアウトしたら、ログイン画面へ移る

**エラー**

| 原因 | 文言 |
|---|---|
| メールアドレスかパスワードが違う | メールアドレスかパスワードが違います |
| メールアドレスの確認が済んでいない | メールアドレスの確認が済んでいません |
| それ以外 | ログインできませんでした。時間をおいてもう一度お試しください |

**関わるもの**：Supabase の認証、`pages/Login/`、`contexts/AuthProvider.tsx`、`components/common/RequireAuth.tsx`（理由は HANDOFF 14「認証の設定」、19「ログインのセッション」）

## F-02 レシピの一覧・検索・絞り込み

**目的**：今日作る料理を、登録したレシピから探す。

**画面**：レシピ一覧（`/`）

**入力**

| 項目 | 決まり |
|---|---|
| 検索 | 料理名かタグに、入れた文字が含まれるものを出す |
| 絞り込み | 1つだけ選べる：すべて／★ お気に入り／⏱ 20分以内／各タグ |

**処理・ルール**
- 新しく登録した順に並べる。削除したレシピは出さない
- 検索と絞り込みは同時に使える
- **⏱ 20分以内**：調理時間が20分以下のもの。タグではなく調理時間から判定する。調理時間が入っていないレシピは含めない
- タグの絞り込みの選択肢は、今あるレシピに付いているタグを重複なしで並べる
- 当てはまるものがなければ「該当するレシピがありません」
- カードからできること：詳細を開く、★ お気に入りの付け外し（F-03）、リクエストに入れる（F-06）
- 写真の機能はまだないので、タグに合わせた絵文字と色を代わりに出す

**関わるもの**：`recipes`（材料・手順も一緒に読む）、`pages/RecipeList/`、`api/recipes.ts`

## F-03 レシピの詳細（お気に入り・ひとことメモ）

**目的**：作るときに、材料と作り方を見る。好みやコツを残す。

**画面**：レシピ詳細（`/recipes/:id`）

**表示するもの**：料理名、タグ、ひとことメモ、調理時間、何人分、作った回数、最後に作った日（なければ「まだ作ったことがない」）、材料、作り方、参考 URL（あれば、別のタブで開く）

**処理・ルール**
- **お気に入り（★）**：夫婦で共通。どちらかが付ければ2人ともお気に入り。一覧のカードからも付け外しできる
- **ひとことメモ**：タップするとその場で書ける。保存すると詳細を読み直す。空にして保存すると消える。保存に失敗したら、書いた内容を残したまま編集を続けられる
- 「編集」で、レシピの編集へ移る（F-04）
- 「戻る」で、来た画面に戻る
- 消されたレシピを開いたときは「レシピが見つかりません」と「レシピ一覧へ」のリンクを出す
- 画面の下に、リクエストに入れるボタンを浮かせて出す（F-06）

**関わるもの**：`recipes`、`cook_logs`（作った回数）、`pages/RecipeDetail/`、`api/recipes.ts`（理由は HANDOFF 11「レシピのひとことメモ」、13「主な判断」）

## F-04 レシピの追加・編集

**目的**：レシピを登録する・直す。

**画面**：レシピの追加（`/recipes/new`）、レシピの編集（`/recipes/:id/edit`）。同じ画面を使い回す

**入力**

| 項目 | 必須 | 決まり |
|---|---|---|
| 料理名 | ✓ | 100文字まで。前後の空白は取り除く |
| 調理時間（分） | | 1以上の数 |
| 何人分 | | 1以上の数 |
| タグ | | 今あるタグをタップで付け外し。新しいタグは入力して追加（20文字まで。先頭の `#` と前後の空白は取り除く。同じタグは2つ付けない） |
| 材料 | | 1行に材料名（100文字まで）と分量。＋ で行を足し、✕ で消す（最後の1行は空にするだけ） |
| 作り方 | | 1ステップ＝1欄。＋ で欄を足し、✕ で消す（最後の1つは空にするだけ） |
| 参考 URL | | |

**処理・ルール**
- 材料名が空の行、空の手順は、保存のときに除く
- **同じ名前のレシピがあるとき**：保存の前に「すでにあります。このまま保存しますか？」と確認する（止めはしない。「肉じゃが（甘め）」のような別のレシピもありうるため）。全角・半角、空白、大文字・小文字の違いは同じとみなす。編集中のレシピ自身とは比べない
- **保存**：レシピ本体・材料・手順を、1つの DB 関数でまとめて書く。途中で失敗したら全部取り消す
- **保存した後**：追加なら一覧へ、編集なら詳細へ移り、「レシピを追加しました／更新しました」と出す。「戻る」でフォームに戻らない
- **キャンセル**：追加なら一覧へ、編集なら詳細へ戻る（保存しない）
- 削除済みのレシピは編集できない（「見つかりませんでした」）
- AI で取り込んだ内容をフォームに入れられる（F-05）
- **レシピを消す機能はまだない**（#13）

**関わるもの**：DB 関数 `save_recipe`、`pages/RecipeForm/`、`components/common/TagSelector.tsx`、`api/recipes.ts`（理由は HANDOFF 18「フォームの入力欄」「タグの選び方」「保存時のお知らせと重複確認」「保存した後の移り先」）

## F-05 AI で取り込む

**目的**：レシピを手で打たずに登録する。

**画面**：レシピの追加・編集の一番上（「🔗 URL」「📷 写真」「📋 テキスト」の3つのボタン）

**入力**

| 方法 | 入れるもの | 決まり |
|---|---|---|
| 🔗 URL | レシピのページの URL | **DELISH KITCHEN・クックパッド・クラシルだけ**。https だけ。2,000文字まで |
| 📷 写真 | レシピの写真・スクショ | アプリの中で長い辺 1600px の JPEG に縮めてから送る |
| 📋 テキスト | コピーしたレシピの文章 | 8,000文字まで |

**処理・ルール**
- 押すと AI が読み取り、料理名・調理時間・何人分・タグ・材料・作り方を**フォームに入れるだけ**。保存はしない（人が確かめてから F-04 で保存する）
- すでに何か入力していたら、置き換えてよいか確認する
- URL から取り込んだときは、その URL を参考 URL に入れる
- **URL のとき**：サーバーがページを取りに行き、ページに埋め込まれたレシピの構造化データ（JSON-LD）を取り出してから AI に渡す
  - 許可した3サイト以外、Instagram、http の URL は取りに行かない
  - 転送は3回まで追い、転送先も許可した3サイトか確かめる
  - 15秒で打ち切り、3MB を超えるページは読まない
- **タグ**：今あるタグの中からなるべく選ばせる（新しいタグは必要なときだけ）
- **材料の印**：★・☆・◎・(A) などの印は、材料名の一部として残す（作り方の「★を混ぜる」とつながるように）
- 読み取りにかかる時間の目安を出す（テキスト10秒・URL 15秒・写真30秒ほど）。その間は3つのボタンを押せない
- 読み取れたら「読み取った内容を入れました。間違いがないか確認してから保存してください」と出す

**エラー**（主なもの）

| 原因 | 文言 |
|---|---|
| URL の形が正しくない | URL の形が正しくありません。https:// から始まる URL を貼ってください |
| 対応していないサイト（http も含む） | このサイトはまだ URL での取り込みに対応していません。レシピの文章をコピーして「📋 テキスト」に貼ってください |
| Instagram の URL | Instagram は URL から読み取れません。投稿の文章をコピーして「📋 テキスト」に貼るか、文章の部分のスクショを「📷 写真」で取り込んでください |
| ページにレシピのデータがない | このページからレシピを見つけられませんでした。レシピの文章をコピーして「📋 テキスト」に貼ってください |
| ページを開けない | ページを開けませんでした。URL が正しいか確認して、もう一度お試しください |
| AI の利用回数の上限 | AI の利用回数の上限に達しました。しばらく時間をおいてお試しください |
| AI の返事が遅すぎる | AI の返事に時間がかかりすぎました。少し時間をおいてもう一度お試しください |
| レシピとして読めない | レシピとして読み取れませんでした。料理名や材料が写っているか確認してください |

**関わるもの**：Edge Function `parse-recipe`（Gemini API を呼ぶのはここだけ）、`components/common/AiImport.tsx`、`utils/parseRecipe.ts`、`utils/image.ts`（理由・構成は HANDOFF 18 全体、特に「URL から取り込む」）

## F-06 リクエスト

**目的**：食べたい料理を入れておき、作る日を決めて、作ったら記録する。

**画面**：レシピ一覧・詳細のボタン、リクエスト（`/todo`）

**処理・ルール**

*入れる*
- 一覧のカード、または詳細の「＋ リクエストに追加」で、**日付未定**で入れる
- 入っているレシピは「✓ リクエスト済み」になり、もう一度は入れられない（日付があってもなくても）。「作った！」か ✕ で外れたら、また入れられる
- シークレットモードのときのボタンは「🙋 食べたい！」になる（F-07）

*リクエストの画面*
- 上に月のカレンダー。予定がある日に料理の絵文字を出す。日付をタップすると、その日の予定までスクロールする
- 下の一覧は3つに分ける：**過ぎた予定**（今日より前）、**これからの予定**（日付ごと。今日・明日は「今日」「明日」と出す）、**日付未定**
- カードには料理名・ひとことメモ・「🙋 食べたい！」の印（相手が付けたもの）を出す。料理名を押すとレシピ詳細へ
- 削除されたレシピは出さない

*日付を決める*
- カードの日付を押すと、iPhone の日付の選択が開く。「消去」で日付未定に戻る
- **同じ日に同じ料理は1つまで**。重なったときは「その日にはすでに同じレシピが入っています」と画面に出す
- 日付未定の同じ料理も1つまで

*作った！*
- リクエストから外して、作ったご飯（F-10）に記録する。1つの DB 関数でまとめて行う
- 記録する日：予定日が今日以前ならその**予定日**（押し忘れたときのため）、未来か日付未定なら**今日**（日本時間）

*✕*
- 確認せずにリクエストから外す（記録はしない）

*保存中*
- 「作った！」か ✕ の保存中は、どのカードのボタンも押せない

**関わるもの**：`todo_items`、DB 関数 `mark_cooked`・`request_recipe`、`pages/Todo/`、`components/common/MonthCalendar.tsx`、`api/todo.ts`（理由は HANDOFF 11「今週作る：予定日とカレンダー」、15「予定日の表示をユーザーごとに分ける」）

## F-07 シークレットモード

**目的**：作る料理と日付を相手に隠す（サプライズにしたい）。予定を見ない側が使う。

**画面**：設定のスイッチ。オンにすると、ほかの画面の見え方が変わる

**処理・ルール**
- **人ごとの設定**。自分の設定だけ読める・変えられる（相手の設定は見えない）。一度も切り替えていなければオフ
- オンのとき
  - 下のタブに「リクエスト」を出さない。`/todo` を直接開いても一覧へ移す
  - 一覧・詳細のボタンは「🙋 食べたい！」。押すと、日付未定の同じ料理がすでにあれば、増やさずにその1件に自分の印を付ける。なければ印付きで入れる（1つの DB 関数でまとめて行う）
  - 「✓ リクエスト済み」は、**自分が「食べたい！」したものだけ**に出す（相手が入れた料理は出さない）
  - 買い物リストで、どの料理の材料かを出さない
- 設定を読み終わるまでは、タブも画面も出さない（一瞬でも予定が見えないように）
- **隠すのは画面だけ**。データそのものは2人とも読める（買い物リストの材料から料理が推測できる可能性は受け入れている）

**関わるもの**：`user_settings`、`todo_items.requested_by`、DB 関数 `request_recipe`、`pages/Settings/`、`components/layout/MainLayout/`、`api/settings.ts`（理由は HANDOFF 15「予定日の表示をユーザーごとに分ける」）

## F-08 買い物リスト

**目的**：買うものを2人で共有する。

**画面**：メモ（`/memo`）の上半分

**入力**

| 項目 | 必須 | 決まり |
|---|---|---|
| 品名 | ✓ | 100文字まで |
| 分量 | | |

**処理・ルール**
- **手入力で追加**：品名と分量を入れて「追加」。保存できたら入力欄を空にする（失敗したら残す）
- **🙋 リクエストの材料から追加**：リクエストに入っている料理の材料を、まとめて足す
  - 同じ料理が何日かに入っていても1回分
  - 同じ料理の同じ材料が、まだ買っていない状態であれば重ねて入れない
  - 足したら「◯品を追加しました。家にあるものは ✕ で消してください」と出す（足すものがなければ「追加する材料はありませんでした」）
  - 冷蔵庫にあるものもあるので、自動では足さない（ボタンを押したときだけ）
  - リクエストが空のときは押せない
- **チェック**：行のどこをタップしても付け外しできる。まだ買っていないものを上、買ったものを下に並べる
- ✕ で1品消す。「買ったもの（◯品）を消す」で、チェックしたものをまとめて消す
- リクエストの材料から足したものは、どの料理の材料かを出す（シークレットモードのときは出さない）

**関わるもの**：`shopping_items`、DB 関数 `add_todo_ingredients_to_shopping`、`pages/Memo/`、`api/shopping.ts`（理由は HANDOFF 11「メモ：買い物リストと共有メモ」）

## F-09 共有メモ

**目的**：冷蔵庫のホワイトボードのように、2人で1枚のメモを共有する。

**画面**：メモ（`/memo`）の下半分

**処理・ルール**
- メモは1枚だけ（追加・削除はできない。書き換えるだけ）
- **自動で保存する**：打ち終わって1秒たったら保存する。入力欄から離れたときは、1秒を待たずに保存する。保存の状態（「保存中…」「保存しました」）を出す
- 書いている途中は、アプリに戻ったときの読み直しで相手の変更が届いても、入力欄を上書きしない
- 2人が同時に書いた場合は、後から保存した方が残る

**関わるもの**：`shared_notes`、`pages/Memo/`、`api/shopping.ts`

## F-10 作ったご飯

**目的**：いつ何を作ったかを振り返る。

**画面**：作ったご飯（`/history`）、レシピ詳細の「作った回数・最後に作った日」

**処理・ルール**
- 記録はリクエストの「作った！」で増える（F-06）。この画面からは足せない
- 新しい順に、**月ごとにまとめて**出す。月の見出しに、その月に作った回数を出す。画面の上に、これまでの合計の回数を出す
- 同じ日に2回作ったときは、後から記録した方を上に出す
- 料理名を押すとレシピ詳細へ。**削除されたレシピの記録も残し**、「（削除済み）」と出す（詳細はないのでリンクにしない）
- その回のメモがあれば出す（書き込む画面はまだない。#25）

**関わるもの**：`cook_logs`、`pages/History/`、`api/history.ts`

## F-11 設定・アプリの情報

**目的**：ログイン中のアカウントを確かめ、表示の設定を変える。

**画面**：設定（`/settings`）

**表示するもの・できること**
- ログイン中のメールアドレス（ローカルのダミーデータなら `@example.com` なので、どちらにつないでいるかの見分けにも使える）
- シークレットモードのスイッチ（F-07）
- アプリ名とバージョン（`package.json` のバージョンの最初の2つ。例：1.1）
- ログアウト（F-01）

**関わるもの**：`pages/Settings/`（バージョンの決め方は HANDOFF 23）
