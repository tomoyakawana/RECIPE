## 通知機能（川名さんの要望、2026-10-22 記録、未実装）

**やりたいこと：** 買い物リストで食材を「買った」にしたら、**相手のスマホに通知**が届く（例：「🛒 牛乳を買いました」）。二重に買うのを防ぐ。

**iPhone の PWA の条件（作るときに一次情報で再確認する）**
- PWA の通知（Web Push）は **iOS 16.4 以降で、ホーム画面に追加したアプリだけ**が受け取れる。Safari で開いたままでは届かない
- 通知の許可は、アプリの中で**ボタンを押してもらってから**求める必要がある（自動で許可を求めることはできない）

**必要になるもの**
- 端末ごとの通知の宛先（push subscription）を DB に保存するテーブル（ユーザーごと・端末ごと、RLS は本人のみ）
- Service Worker に、通知を受け取って表示する処理（vite-plugin-pwa の設定変更が必要になる見込み）
- 「買った」にチェックが入ったら、Edge Function から相手の端末に送る（DB の変更をきっかけにする方法か、フロントから呼ぶ方法かは作るときに決める）
- 通知を送るための鍵（VAPID キー）を Supabase の Secrets に置く

**費用：** Web Push 自体は無料の仕組みで、Edge Function の無料枠で動く見込み。作るときに一次情報で確認する

**作るときに決めること**
- 誰に送るか（相手だけ／自分にも）
- 何品もまとめて買ったとき、1品ずつ通知するか、まとめて1回にするか
- 通知のオン・オフを設定画面で切り替えられるようにするか

**順番：** 買い物リストを DB につないでから（モックのままだと、相手の画面に変更が届かないため）。Realtime（相手の画面への即時反映）とあわせて考える

## 友達に配る場合（需要が出たら検討）

- PWA なので URL を送れば配れる。ただし今の設計は「ログイン済みは全データを読み書きできる」なので、そのままでは他人に川名さん夫婦のデータが見えてしまう
- 配るなら**家庭（世帯）ごとにデータを分ける**（`households` テーブル、各テーブルに `household_id`、RLS を「自分の家庭のデータだけ」に変更）。データが入った後でもマイグレーションで追加できる
- 技術以外：無料枠（写真の容量、Gemini）を全員で分け合う、人のデータを預かる責任、問い合わせ対応
- 2026-10-20 時点の判断：**需要が出たら対応する**（欲張らない）
