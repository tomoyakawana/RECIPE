# AI でレシピを取り込む（機能5、2026-10-21）

[← 目次（HANDOFF.md）](../../HANDOFF.md)

## 構成
```
アプリ（AiImport：📷 写真から／📋 テキストから）
  └ utils/parseRecipe.ts → supabase.functions.invoke('parse-recipe')
        ↓ ログインしている人だけ（verify_jwt ＋ withSupabase({ auth: 'user' }) の二重確認）
Edge Function「parse-recipe」（supabase/functions/parse-recipe/）
  └ Gemini を呼ぶのはここだけ（SSAM の ai_service.py と同じ考え方）。API キーは Secrets の GEMINI_API_KEY
  └ 入力（文章 8,000 文字まで／画像は JPEG・PNG・WebP で約3MBまで）と、Gemini の答えを Zod で検証
        ↓
フォームに入れるだけ。保存はしない（人が確認・修正してから保存する）
```

| 項目 | 内容 | 理由 |
|---|---|---|
| モデル | `gemini-3.5-flash-lite` | 無料枠の対象（2026-10-21 公式の料金ページで確認）。SSAM と同じモデル |
| モデルの切り替え（#71、2026-11-16） | Secrets の `PARSE_RECIPE_MODEL` にモデル名を入れると、そのモデルを使う。入れていない・空のときは、コードの既定（`DEFAULT_MODEL`）を使う。ログの `model=` で、どれが使われたか分かる | 別のモデルに変えることもありうるので、コードを直さずに切り替えられるようにする（川名さん）。献立提案（#11）も同じ形（`SUGGEST_MENU_MODEL`）にそろえる。変数は関数ごとに分ける（1つにすると、片方だけ変えられない） |

**モデルの切り替え方（#71）**
- 本番：`npx supabase secrets set PARSE_RECIPE_MODEL=モデル名`。**再デプロイは要らない**（公式「Your functions read a new secret immediately, so you don't need to redeploy.」2026-11-16 確認）。既定に戻すときは `npx supabase secrets unset PARSE_RECIPE_MODEL`
- ローカル：`supabase/functions/.env` に `PARSE_RECIPE_MODEL=モデル名` を足し、`npx supabase stop` → `npx supabase start`（`.env` は start のときに読まれる）
- 間違ったモデル名を入れると、Gemini が 404 を返し、アプリには「AI での読み取りに失敗しました」と出る。ログに `Gemini error model=…` が出るので、そこで気づける
- 無料枠の対象かどうかはモデルごとに違う。変える前に、公式の料金ページで確かめる
- ローカルで確認したこと（2026-11-16）：設定なし → 既定のモデルで取り込めた／間違った名前 → 502 と上のメッセージ、ログに model=…／空の値 → 既定のモデル
- **本番の parse-recipe は v1.3 まで develop の版で動く**（#71 は main に先に載せず、v1.3 にまとめる。設定しなければ動きは前と同じ）
| テキストから取り込む | iPhone のテキスト認識表示（Live Text）でコピーした文字や、レシピサイトの文章を貼り付ける | 川名さんの発案。写真より送るデータが小さく、無料枠の節約になり、写真そのものを外に出さずに済む |
| 写真から取り込む | アプリ側で長い辺 1600px・JPEG に縮小してから送る（`utils/image.ts`） | iPhone の写真は大きいため、送る量と時間を減らす |
| 答えの形 | Gemini に JSON の形（`responseSchema`）を指定。作り方は配列で1要素＝1ステップ、1ステップの中では改行しない | フォームの入力欄（1ステップ1欄）にそのまま入れられる |
| AI への指示 | 書かれていないことを推測で足さない／材料は名前と分量に分ける／番号は外す／広告などは無視／レシピでなければ isRecipe = false | 読み間違いより「勝手に足す」方が気づきにくいため |
| エラー | 上限（429）、読み取り失敗、レシピではない、などを日本語で返す | — |

## Gemini の無料枠について（2026-10-21 確認）
- **無料枠では、送った内容が Google の製品改善に使われる**（有料枠では使われない）。送るのはレシピの文章・写真なので許容した。**家族の写真や個人情報が写った写真は送らない**
- 請求先アカウントは登録していない（＝無料枠のまま。課金されない）。キーは川名さんの個人の Google アカウントで発行
- 回数の上限は公式ページに数字がなく、**Google AI Studio の画面で確認する**。1日の上限は太平洋時間の0時にリセット

## 時間切れの対応（2026-10-22）
- **症状：** 本番で写真・テキストとも取り込めなかった。ログは `[parse-recipe] unexpected TimeoutError: Signal timed out.`
- **原因：** Gemini を待つ時間を **30秒** にしていたが、Gemini の返事がそれを超えていた（約1,000文字のテキストでも）。画像の大きさが原因ではなかった（テキストでも同じだったため）。考える処理（thinking）は `gemini-3.5-flash-lite` では既定で一番軽い minimal（公式で確認）なので、原因ではなさそう
- **対応：**
  - 待つ時間を **90秒** に（Edge Function は無料プランでも1回 **150秒** まで動ける。2026-10-22 公式で確認）
  - 時間切れのときは「AI の返事に時間がかかりすぎました」と返す（以前は「想定外のエラー」扱いで分かりにくかった）
  - 1回ごとに、かかった時間・文章か画像か・大きさ・トークン数（考える処理の分も）をログに残す（`[parse-recipe] ok …` / `timeout …`）。中身や API キーは出さない
  - 画面の待ち時間の目安を、写真のときは「30秒ほど」に
- **プロンプトの改善：** Live Text でコピーすると、**材料名の列と分量の列が別々にまとまって**出てくる（キッコーマンのレシピで確認）。「材料名だけ続いた後に分量だけ続く場合は、上から順番に対応づける」「栄養成分・アプリの宣伝・シェアボタンは無視する」を追加
- **縦長のフルページのスクショ：** 今は「長い辺を 1600px」に縮めるので、極端に縦長だと幅が細くなって文字が潰れる。ただ、**関係ない部分をトリミングして6割ほど残したスクショでは問題なく読めた**ので、**縦に切り分けて送る処理は保留**。トリミングなしで材料や手順が抜ける・時間切れが増えるようなら作る

## フォームの入力欄（2026-10-21 変更）
- 作り方を「1つの大きな欄に改行で区切る」形から、**1ステップ＝1欄**（番号付き、＋で追加、✕で削除）に変更（川名さんの指摘）。材料にも ✕ を付けて揃えた。最後の1行は消さずに空にする
- 空の欄は保存時に除く。入力した数と詳細画面の表示数が一致することを、ブラウザでの自動操作で確認した

## タグの選び方と AI のタグ付け（2026-10-23）
- **タグの入力**：文字で打つ形から、**今あるタグをチップで並べてタップで付け外し**する形に変更（`components/common/TagSelector.tsx`）。新しいタグは入力して Enter か「＋ 追加」。先頭の `#` は除く、20文字まで。**日本語の変換を確定する Enter では追加しない**（`isComposing` で判定）。Enter でフォームが保存されないようにしている
- **AI のタグ付け**：AI 取り込みのとき、**今あるタグの一覧も Edge Function に送り**、「この中から優先して選ぶ（表記も同じに）、どうしても当てはまらない場合だけ新しく作る、5個まで」と指示する。目的は「和食」と「和風」のような**表記ゆれを防ぐ**こと（絞り込みと、将来の献立提案 #11 の「似たものを避ける」の精度に効く）。Edge Function は版 4
- 送る既存タグは、Edge Function の入口の上限（20文字・100個）に合わせて、アプリ側で先にそろえる（はみ出すと読み取り自体が失敗するため）
- マイグレーションなし（`recipes.tags` の配列をそのまま使う）。ジャンル（和食・洋食・中華）を別の列に分ける案もあったが、**今あるタグで十分**（川名さん判断）

## 保存時のお知らせと重複確認（2026-10-22）
- **トースト**：レシピを追加・更新すると、画面上部に「✓ レシピを追加しました／更新しました」が3秒出る。SSAM の ToastContext と同じ使い方（`const toast = useToast(); toast.success('…')`）。成功（黒）とエラー（赤）の2種類。ほかの操作にも1行で付けられる
- **削除の機能はまだない**（DB は論理削除の設計済み。必要になったら編集画面の一番下に作る想定）
- **料理名の重複確認**：保存するとき、同じ料理名のレシピがあれば「このまま保存しますか？」と確認する（止めはしない。「肉じゃが（甘め）」のような同じ料理の別レシピもありうるため）。全角・半角（NFKC）、空白、大文字・小文字の違いは無視して比べる。編集中の自分自身とは比べない。DB には一意制約を付けていない
- **保存した後の移り先（2026-11-03 変更、#42）**：**追加したら一覧**（続けて次のレシピを探して取り込める）、**編集したら詳細**（直した結果をその場で確かめられる。編集は詳細から入るので、元に戻る形）。以前はどちらも詳細だった（川名さんの要望）
- **保存した後は一番上から見せる（2026-11-03、#51 の PR で）**：このアプリには画面が変わったときにスクロールを戻す仕組みがなく、長いフォームの一番下で保存すると、移った先の一覧・詳細が途中の高さから表示されていた。更新したときも一覧へ、という案も出たが、編集は1つのレシピに用があるときなので詳細のまま（川名さん判断）
  - **最初は保存が成功したときだけ** `window.scrollTo` で戻していたが、一覧の途中でレシピを押すと詳細も途中の高さから始まることに気づき（川名さん）、**MainLayout で「進む」移動（PUSH・REPLACE）のときは一番上へ**にまとめた（react-router の `useNavigationType`）。保存の後の移動も REPLACE なのでこれで足り、フォームの `scrollTo` は外した
  - **「戻る」（POP。iPhone の左端からのスワイプも）では何もしない**。どんな移動でも一番上に戻すと、一覧 → 詳細 →「戻る」で一覧の見ていた位置を忘れるため。戻ったときに一覧の位置まで戻れるかはブラウザ次第

## URL から取り込む（#42、2026-11-03）
- **きっかけ**：フルページのスクショは撮るのに時間がかかり（画像が大きい）、読み取れるかも確実でなく、手間とストレスが大きかった（川名さん・奥さん）
- **仕組み**：Edge Function がページを取りに行き、ページの中の **JSON-LD（schema.org の Recipe）だけ**を取り出す。使う項目（料理名・人数・時間・ジャンル・材料・手順）だけを文章にして、今までの「テキストから」と同じ流れで Gemini に渡す。画像・作者・コメントなどは渡さない。ページ全体は 150〜340KB あるが、渡すのは数百文字で、**1.3〜1.8秒**で返ってきた（ローカルで確認）
- 構造化データはすでに整っているが、**AI を通す**のは、材料を名前と分量に分ける・既存のタグから選ぶ、を今の仕組みに任せられるため

| 判断 | 理由 |
|---|---|
| **取りに行く先は許可リストのサイトだけ**（DELISH KITCHEN・クックパッド・クラシル。`www.` の付け外しも含む。#63 で Nadia・キッコーマンを足して5サイト） | 奥さんがよく見るサイト。任意の URL を取りに行かせると、サーバーの中の外から見えない場所をのぞかれる危険（SSRF）があり、Edge Function の中でどこまで防げるかは確認していない。許可リストなら決めたサイトにしか行かない |
| **サイトを増やすときは、コードに1行足して PR → 本番に反映** | 読み取りは共通の形式（JSON-LD）なので、サイトごとの専用コードは要らない。足す前に、そのページに JSON-LD の Recipe があるかを確かめる（なければ足しても読めない）。**アプリ上で足せる形は見送り**：DB・設定画面・権限が増えて今回のリリースに収まらない。足しても読めないサイトがあり迷わせる。アカウントが乗っ取られたとき、どこへでも行けてしまう |
| 転送は自動で追わない（3回まで、毎回許可リストと照らす）。`https` だけ、15秒・3MB まで | 転送先が許可リストの外だった場合に、そこへ行く前に止めるため |
| 対象外のサイトは「まだ対応していません。📋テキストに貼ってください」 | その場は今ある取り込み方で困らないようにする |
| **Instagram は対象外**。URL が貼られたら、キャプションをコピーして📋テキストに貼るか、キャプションのスクショを📷写真で、と案内する | ログインしないと中身（キャプションも JSON-LD も）がページに入っていない（2026-11-02 確認）。アプリから取りに行っても、ブラウザの仕組み（CORS）で読めず、Instagram のアプリのログインも使えない。自動での情報の収集は規約で禁止されている（細かい点は一次情報で要確認） |
| 取り込んだ URL は、参考URL の欄に自動で入れる | 元のページにすぐ戻れるように |
| 画面は「🔗 URL」「📷 写真」「📋 テキスト」のボタン3つ。最初は何も選ばない。URL・テキストは押すと入力欄が開き、写真は押すとそのまま写真の選択が開く | プルダウンは iPhone だと選ぶのに手間が増える。写真は今までどおり1タップ |

- **★・(A) などの印は残す**：クックパッドの「★ごま油」の★を AI が消して、手順の「★の調味料を加えて」と食い違った。指示と答えの形（材料名の説明）に「印は消さずに残す」を足した。URL 取り込みでは★は毎回残るようになった。テキスト取り込みの (A) は、まだ消えることがある（2回に1回）
- **分かっている癖**：DELISH の「8本分」は人数の欄に 8 と入る（人数は数字の欄のため）。クラシルの手順の (A)・(B) は、構造化データに材料との対応がないので、材料の側には付かない（参考URL から元のページを開いて確かめる）
- **改行入りの JSON-LD（#63、2026-11-14）**：キッコーマンの読みものページ（`/homecook/tsushin/…`）は、JSON-LD の文字列の中に改行がそのまま入っていて、JSON としては壊れている（`JSON.parse` が失敗し「レシピを見つけられませんでした」になる）。通常のレシピページ（`/homecook/search/recipe/…`）は正しい。読む前に、制御文字（`\u0000`〜`\u001f`）を空白に置き換えるようにした。正しい JSON では制御文字は文字列の外（区切りの空白）にしか出てこないので、意味は変わらない。5サイトで、置き換えの前後で読み取った中身が同じことを確認した。lint の `no-control-regex`（制御文字の正規表現は書き間違いが多い、という警告）は、わざとなのでその1行だけ止めた
- **確認していないこと**：本番では Supabase のサーバーから取りに行く。サーバーからのアクセスを弾くサイトがあるかもしれないので、本番に反映した後に3サイトで試す
  - Nadia・キッコーマン（#63）も、本番に反映した後に試す。キッコーマンは `www` なしの URL がつながらない（2026-11-14 確認）ので、許可リストには `www.kikkoman.co.jp` だけを入れた
