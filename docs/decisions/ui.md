## 雛形（2026-10-17 作成）

### 構成
| 項目 | 採用 | 理由 |
|---|---|---|
| ビルドツール | **Vite**（`create-vite` 9.2.1 の `react-ts` テンプレート） | React + TS の公式推奨の始め方。設定が少なく開発サーバーが速い |
| PWA 化 | **vite-plugin-pwa** 2.0.0 | manifest と Service Worker（Workbox）を自動生成する定番プラグイン。SW を手書きしなくて済む。vite 8 対応を peerDependencies で確認済み |
| SW 更新方式 | `registerType: 'autoUpdate'` | 2人で使うアプリなので「更新しますか？」の確認 UI は不要。デプロイ後に自動で新版へ切り替わる |
| Lint | oxlint（テンプレート標準のまま） | テンプレートの既定。変える理由がない |

確認時の主なバージョン：vite 8.3.4 / React 19.2 / TypeScript 6.0。

### iOS 向けに入れたもの
- `manifest`：`display: standalone`、日本語名「なに食べたい？」（2026-10-18 に「レシピ」から変更）、テーマ色 `#e8743b`
- `index.html`：`apple-touch-icon`、`apple-mobile-web-app-*` の meta、`viewport-fit=cover`
- `index.css`：`env(safe-area-inset-*)` でノッチ・ホームバーを避ける余白
- アイコン（192 / 512 / apple-touch-icon 180）は**仮**。お椀のシンプルな図形

### まだ入れていないもの（意図的）
Supabase、ルーティング、UI ライブラリ、状態管理。必要になった時点で決める。

### 注意
- **`npm install` は Mac で実行すること。** Claude の作業環境（Linux VM）で入れた node_modules は Mac では動かない（esbuild/rolldown 等のネイティブバイナリが OS 別のため）
- PWA の Service Worker は `npm run dev` では動かない。確認は `npm run build` → `npm run preview`

## レスポンシブ方針・CSS（2026-10-17 決定）

**対象は PC と iPhone の両方**（Android は引き続き対象外）。

### 方針
| 項目 | 決定 | 理由 |
|---|---|---|
| 基本の考え方 | **モバイルファースト**。iPhone 幅を基本のスタイルにして、`md:`（= `min-width`）で PC 向けを足す | SSAM はデスクトップ前提の土台にあとからスマホ対応を足そうとして崩れた。最初からスマホ基準で作れば同じことは起きない |
| ブレークポイント | ~~まずは 768px（Tailwind の `md:`）の1つだけ~~ → **`md:`（768px）と `lg:`（1024px）の2つ。一覧の列だけ `xl:`（1280px）も使う**（2026-11-14、#26 で変更） | 最初は2画面幅しか想定していなかった。PC で登録・整理する場面のために、PC 用の形を `lg:` から足した。`md:` の形（上のメニュー）は、iPad の縦・狭いウィンドウ用として残す。詳しくは下の「PC の画面（#26）」 |
| 一覧の表示 | テーブルではなく**カード形式**。PC では列数を増やす | 狭い幅で横スクロールさせない |
| 操作 | ホバー前提の UI は作らない。タップ領域は **44px 以上** | タッチ操作が主。44pt は Apple の推奨値 |
| 確認方法 | PC ブラウザの開発者ツール（iPhone サイズ表示）＋ iPhone 実機（LAN 経由） | — |

### PC の画面（#26、2026-11-14）
iPhone・`md:` のクラスには触らず、**`lg:` のクラスを足すだけ**で作った（モバイルファーストにしていたので、外枠の `MainLayout` と各画面に数行ずつで済んだ）。

| 項目 | 決定 | 理由 |
|---|---|---|
| ナビ | `lg:` で**左に固定のサイドバー**（幅 224px）。上にアプリの名前、設定だけ一番下に離す | 上の横並びより、項目が増えても詰まらない。設定は毎日使う画面と分ける |
| サイドバーの色 | 背景は**薄いオレンジ**（`bg-brand/12`）、今いる画面だけ＋ボタンと同じ濃いオレンジ | 最初は背景全体を濃いオレンジにしたが、強すぎた（川名さん）。色は「今いる場所」に絞る |
| サイドバーをたたむ（ドロワー） | **入れない** | 一度作って触ってみたが、この画面ではたたむ操作がむしろ手間になった（川名さん） |
| 本文の幅 | 最大 896px → **1152px**（`lg:max-w-6xl`）。サイドバーの分を除いた幅の中で中央に置く | 大きい画面で左右が余っていた |
| レシピ一覧 | iPhone 2列 / `md:` 3列 / `lg:` **4列** / `xl:` **5列** | 一度にたくさん見渡せるように |
| 追加・編集 | `lg:` で**2列**：左に写真・料理名・時間・タグ、右に材料・作り方・参考URL。保存ボタンは幅を決めて中央 | 縦に長い入力が1画面に収まりやすい。iPhone での並び順を変えないよう、参考URL は右の最後に置いた |
| 追加・編集の「できあがりのプレビュー」 | **入れない** | 詳細の表示をフォームの中でもう1つ組み立てることになり変更が大きい。入力欄が1列のまま残り、縦に長い問題が解決しない |
| リクエストのカレンダーを大きくする（1日のマスに料理名） | **入れない**。今のまま（`md:` からカレンダー｜予定の一覧の2列） | 今の形で足りている（川名さん）。マスに料理名を出すには MonthCalendar の作り直しになり、変更が大きい |
| タブレット | 専用の形は作らない。iPad の横・13インチの縦は PC の形、iPad・Air・Pro 11インチの縦は `md:` の形、**iPad mini の縦（744px）は iPhone の形** | 開発者ツールで見て、どれも使える形だった。iPad mini は今後使う可能性があるので、実際に使って気になったら考える |

### CSS：Tailwind CSS v4
| 項目 | 内容 |
|---|---|
| 採用 | `tailwindcss` 4.3.3 ＋ `@tailwindcss/vite` 4.3.3（Vite 8 対応を peerDependencies で確認） |
| 理由 | SSAM で使い慣れている。`md:` などでレスポンシブを HTML 側に書ける。追加費用なし |
| SSAM（v3）との違い | `tailwind.config.js` / `postcss.config.js` は不要。CSS に `@import "tailwindcss";` の1行。テーマのカスタマイズは CSS の `@theme { }` に書く。クラスの書き方はほぼ同じ |
| Tailwind に任せないもの | `env(safe-area-inset-*)` のノッチ回避余白は `index.css` に素の CSS で残す |

## 画面モック（2026-10-17 作成）

### 進め方：先にモック、データ構造は逆算（2026-10-17 決定）
| 項目 | 内容 |
|---|---|
| 決定 | 先に全画面のモックを作り、そこから必要なテーブル・カラムを逆算する |
| 理由 | 要件がまだふわっとしていて、画面を触って初めて「これも記録したい」と気づくことが多い。業務システムのように要件が固まっていればデータモデルが先だが、今回は逆。Supabase のプロジェクトを後回しにできる（1週間で一時停止する件を気にしなくて済む）利点もある |
| 注意 | 画面に出ない項目（作成者・作成日時・並び順）、関係（1レシピを何回作ったか、お気に入りは夫婦共通か人ごとか）、操作（ボタンを押したら何が起きるか）は、画面からは見えないので逆算のときに抜けやすい |

モックのデータは型付きで書いている。**`src/types/` の型がテーブル定義の下書き**、**`src/contexts/mockStore.ts` の関数一覧が DB への操作の下書き**になる。

### 画面
| 画面 | URL | 対応する機能 |
|---|---|---|
| レシピ一覧 | `/` | 1. レシピ管理 / 4. お気に入り |
| レシピ詳細 | `/recipes/:id` | 1. レシピ管理 |
| レシピ追加 | `/recipes/new` | 1. レシピ管理 / 5. 画像から取り込み（今は写真を選ぶところまで） |
| 今週作る | `/todo` | 3. ワンアクションで TODO に（2026-10-18：予定日とカレンダーを追加） |
| メモ | `/memo` | 買い物リスト・共有メモ（2026-10-18 追加。構想の5機能にはなかったもの） |
| 作ったご飯 | `/history` | 2. 履歴 |

モックのデータはメモリ上だけに持つ（リロードで初期データに戻る）。サーバーを正にする方針のため、ローカルストレージには保存しない。

### 技術
| 項目 | 採用 | 理由 |
|---|---|---|
| ルーティング | **react-router 8.4.0**（宣言的な `BrowserRouter` / `Routes` / `Route`） | SSAM（react-router-dom v7）と同じ書き方ができる。v8 でも使う部品（`BrowserRouter`・`NavLink`・`useParams` など）が揃っていることを確認済み。v8 からパッケージ名は `react-router` |
| 画面間のデータ共有 | React Context（`MockStoreProvider` + `useMockStore`） | モックの間だけの仮置き。DB につないだら中身を差し替える |

### 今週作る：予定日とカレンダー（2026-10-18 決定）
| 項目 | 決定 | 理由 |
|---|---|---|
| 追加のしかた | 一覧・詳細の「＋今週作る」は**日付未定でワンタップ追加**。日付は今週作る画面で後から決める | 要件3「ワンアクションで載せる」を崩さないため |
| 重複のルール | 同じレシピでも**日付が違えば何度でも**入れられる。同じ日に同じレシピ、日付未定同士は1つまで（SQL では `unique nulls not distinct (recipe_id, planned_on)`） | カレーを月曜と金曜に作る、などがありえる |
| 「作った！」で記録する日付 | 予定日が**今日以前ならその予定日**、未来・未定なら**今日** | 作った日に押し忘れて翌日押しても正しい日付が残る。予定より早く作ったときは今日が正しい |
| 日付の選び方 | ブラウザ標準の `<input type="date">`（iPhone では iOS 標準のカレンダーが出る）を、透明にしてボタンに重ねる | 追加ライブラリ不要で、iPhone の操作感になじむ。見た目に不満が出たら自作やライブラリを検討する |
| 画面のカレンダー | 月表示（日曜始まり）。予定のある日に料理の絵文字を出し、タップでその日の予定までスクロール | どの日に何を作るかを一目で見られるように |

### メモ：買い物リストと共有メモ（2026-10-18 決定）
| 項目 | 決定 | 理由 |
|---|---|---|
| タブ名 | 「メモ」（📝） | 川名さんの指定 |
| 買い物リスト | 手入力のチェックリスト。買ったらチェック → 「買ったものを消す」でまとめて削除 | — |
| 今週作るの材料から追加 | **ボタンを押したときだけ**まとめて追加。どのレシピの材料か表示する。同じレシピが複数日に入っていても1回分、未購入の同じ材料（同じレシピ・同じ名前）は重ねない | 冷蔵庫にあるものもあるので自動では入れない。いらないものは ✕ で消してもらう |
| 共有メモ | **1枚だけ**（SQL では `shared_notes` を id = 1 の1行に固定し、更新だけ許可） | 冷蔵庫に貼るホワイトボードの感覚。シンプルさ優先 |
| DB 接続時の検討事項 | 夫婦で同時に使う（片方がスーパー、片方が家）場面があるので、Supabase Realtime で相手の変更を即反映するのが候補。メモの保存は入力のたびではなくデバウンスする | — |

### レシピのひとことメモ（2026-10-18 決定）
| 項目 | 決定 | 理由 |
|---|---|---|
| 中身 | 「玉ねぎ多めが好き」など、レシピそのものに付けるコツや好み。夫婦で共通、1レシピに1つ（SQL：`recipes.note`） | 作ったご飯の「その回のメモ」（`cook_logs.memo`）とは別物 |
| 編集のしかた | 詳細画面でタップしてその場で編集。**編集フォームでは扱わない**（`RecipeInput` から `note` を除外し、フォーム保存時は元のメモを引き継ぐ。`save_recipe` も `note` に触らない） | フォームで保存したときにメモが消える事故を、型で防ぐ |
| 表示する場所 | 詳細画面と、今週作るのカード（1行だけ小さく） | 作るときに思い出せるように。一覧・買い物・作ったご飯には出さない（窮屈・紛らわしいため） |

### 見た目の方針
- 背景はクリーム色（`--color-cream: #fdf8ec`）、カードは白＋柔らかい影、角は大きめに丸める
- 一覧は写真が主役のカード（iPhone 2列 / PC 3列。#26 で PC は4〜5列に）。写真がない間は、タグに合わせた絵文字＋グラデーションを仮の写真にする
- iPhone は画面下に浮いたタブバー、PC は上に横並びのメニュー（タブは レシピ / 今週作る / メモ / 作ったご飯 の4つ）。#26 で、PC の幅（`lg:`）は左のサイドバーに変えた（上の「レスポンシブ方針・CSS」）
- iOS の Liquid Glass は Web では完全には再現できない（ネイティブは SwiftUI の `.glassEffect()`）。今は入れない
