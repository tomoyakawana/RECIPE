# レシピの写真（#14、2026-11-07〜09）

[← 目次（HANDOFF.md）](../../HANDOFF.md)

**写真は Supabase Storage の非公開バケット `recipe-images` に置き、DB（`recipes.image_path`）にはパスだけを入れる。** 定義は [docs/internal/DATABASE.md](../../docs/internal/DATABASE.md) の「Storage（写真）」。

**無料枠（2026-11-07 に公式で確認。変わることがあるので、気になったら一次情報で確かめ直す）**：保存 1GB、egress 5GB／月（DB・Auth などと共通。キャッシュから返した分は別に 5GB）、1ファイル 50MB。画像の変換（Image Transformations）は Free では使えない。超えても課金はされず、通知と猶予のあとに制限がかかる。

| 決めたこと | 理由 |
|---|---|
| **非公開**のバケット＋期限付きの URL（1時間） | 家の料理の写真でも、URL を知っているだけの人には見せない。ログイン済みなら、夫婦どちらも全部の写真を読める・上げる・消せる（データは夫婦で共通、の方針どおり） |
| 縮小は**アプリの中**（canvas）で行い、**詳細用 1200px と一覧用 400px の2つ**を上げる | Free では画像の変換が使えない。iPhone の写真（数MB）をそのまま置くと、容量も egress もすぐ減る。一覧で大きい写真を読むと egress の無駄になる。2つで1枚あたり 300KB ほど（1GB で 3,000 枚ほど） |
| DB には**詳細用のパスだけ**。一覧用は同じフォルダーの `small.jpg` として、アプリで組み立てる | 列を増やさずに済む。2つは必ず組で上げ・組で消す |
| フォルダー名は毎回**ランダムに新しく作り**、上書きしない（update の権限も付けない） | 上書きすると、ブラウザや CDN のキャッシュに古い写真が残る。差し替えは「新しく上げる → 保存 → 古いものを消す」 |
| フォルダー名は `crypto.getRandomValues` で作る（`crypto.randomUUID` を使わない） | `randomUUID` は https か localhost のページでしか使えない。iPhone の実機確認で使う LAN の開発サーバー（`http://<Mac の名前>.local`）では無く、保存が失敗した（2026-11-09） |
| アップロードは**保存の処理（`useSaveRecipe`）の中**で、`save_recipe` の前に行う。保存に失敗したら上げた写真を消し、保存できたら前の写真を消す | 「保存中…」の表示・二重送信の防止・失敗のトーストを、今の仕組みのまま使える。DB と Storage はまたいでトランザクションにできないので、失敗したときの後片付けをアプリで行う。前の写真を消すのに失敗しても、保存は成功のまま（ファイルが1つ残るだけ） |
| `save_recipe` に `p_image_path text default null` を足す（古い関数は drop してから作り直す） | 引数が変わると別の関数として増えてしまう。既定値があるので、DB を先に変えても、写真を渡さない今のアプリがそのまま動く。**編集のときも渡した値で置き換える**ので、アプリは写真を残すときも今のパスを渡す |
| 表示の URL は `useImageUrls` で**全レシピの分を1回でまとめて**取り、写真の部品（`RecipePhoto`）どうしで使い回す | TanStack Query は同じ名札なら通信が1回。一覧のカードが何枚あっても1回で済む。URL を発行するだけなら写真のデータは送られない（egress はほぼ使わない）。50 分ごとに取り直して、期限切れを防ぐ |
| 写真がない・URL がまだ・読み込めないときは、今までの絵文字の枠（`ImagePlaceholder`）を出す | 写真のないレシピも今までどおりの見た目。読み込めなかった URL を覚えておき、取り直して URL が変われば、もう一度写真を出してみる |
| 削除したレシピの写真は消さない | レシピは論理削除なので、戻せるように残す。履歴には出さない（絵文字の枠） |

**本番への反映の順番**：プレビュー（develop）も本番の DB を使うので、**develop にマージする前に `db push`** する。`db push` の後に `npm run gen:types`（`--linked`）で型を作り直す（`save_recipe` の Args に `p_image_path?: string` が増えるだけのはず。`--local` は道具の版が古く、型の形が変わるので使わない）。
